# Official source matrix

Every public New Relic operation must map to current official documentation. This
matrix was reviewed on **2026-07-15**. Source code stores a `sourceUrl` beside each
fixed operation so undocumented schema cannot silently enter the catalog.

New Relic's GraphQL explorer can reveal fields that are not publicly supported.
Introspection alone is not sufficient for inclusion. If a documented API is removed,
deprecated, or materially changed, disable the affected operation and release a
documented compatibility update rather than inventing a fallback.

The shared client enforces the official [25-call NerdGraph concurrency
limit](https://docs.newrelic.com/docs/apis/nerdgraph/nerdgraph-usage-limits/) and
the documented complex-NRQL limit independently.

For field-level signature verification, maintainers also compare the documented
operations with New Relic's official generated
[`newrelic-client-go`](https://github.com/newrelic/newrelic-client-go) types and
documents. Public documentation remains the inclusion authority; generated code
is used to avoid guessing variable, enum, and response-field names.

Telemetry wrappers query documented event types through NRQL: logs use `Log`,
metrics use `Metric`, traces use `Span`, errors use `TransactionError`/supported
error events, issues use `NrAiIssue`, incidents use `NrAiIncident`, and audit history
uses `NrAuditEvent`. The wrapper supplies bounds and
never changes the underlying data entitlements.

## Explicitly unsupported

| Exclusion                            | Reason                                                                                                                    |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| Raw GraphQL                          | Defeats fixed-operation validation, account policy, redaction, and mutation gates.                                        |
| REST v2 fallback                     | NerdGraph is the supported query/configuration plane for this server.                                                     |
| Telemetry ingest                     | Requires different endpoints/keys and is outside the read/configuration boundary.                                         |
| Service-level delete                 | No supported delete mutation in current public SLM documentation.                                                         |
| API-key creation                     | Returns secret-bearing material; use New Relic UI/Terraform/operator workflow.                                            |
| Synthetic secure-credential mutation | Secret lifecycle is intentionally out of band.                                                                            |
| Live-dashboard password/reset        | Secret/public exposure risk.                                                                                              |
| Historical-export download URLs      | Presigned URL exfiltration risk.                                                                                          |
| Slack destination creation           | New Relic requires an OAuth/UI flow; no supported direct mutation workflow.                                               |
| Arbitrary entity delete              | Entity types have different lifecycle semantics and some reappear from telemetry.                                         |
| Golden-data override                 | Current generated contracts do not expose a stable override input matching the older documented context/domain signature. |
| Access-grant update                  | No stable generated input contract is available for the documented inline update shape.                                   |
| Private-location VSE/runtime keys    | Secret-bearing runtime enrollment stays in the New Relic operator workflow.                                               |
| Legacy drop rules                    | Scheduled end of life; use current Pipeline Control operations.                                                           |

## Review process

At least once per release, a maintainer must open each source used by changed
operations, confirm the operation name/input/output and API status, run contract
fixtures for schema drift, and update the review date. Preview and experimental
operations require review even when unchanged.
